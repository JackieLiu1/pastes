# 平台接口与实现边界

完整分层、数据所有权和验证入口见 [工程架构](architecture.md)。
`platform/` 构建为独立的 `pastes_platform`，实现应用层的 `ClipboardFeed` 接口，
通过 `ClipboardController` 进入历史服务；平台代码不包含项目界面或存储实现。

UI 负责“做什么”：显示历史、选择条目、复制数据、展示设置和播放动画。
平台层负责“如何与系统交互”：监听剪贴板、识别来源、恢复粘贴目标、设置原生窗口和注册快捷键。
两层通过普通 C++ / Qt 接口连接，不把原生句柄或 SDK 头文件传进 UI。

```text
MainWindow / HistoryView / PasteItem / AppDialog / SettingsDialog
                       │
          platform/ 公共接口与 Qt 门面
                       │
       ┌───────────────┼────────────────┐
 platform/windows  platform/macos  platform/linux
       └───────────────┴────────────────┘
             platform/desktop
       Windows、Linux 共用的 Qt 窗口与菜单行为
```

## 接口按职责划分

| 公共接口 | 责任 | 调用约束 |
| --- | --- | --- |
| `clipboardsource.h` | 剪贴板变化通知、采集许可、复制来源图标、快照同步和等待时间 | GUI 线程调用；异步图标只传 `QImage`，用请求编号匹配条目 |
| `pastetarget.h` | 唤出前记住目标应用，面板隐藏后恢复焦点并粘贴 | GUI 线程调用；平台实现持有原生目标和取消状态 |
| `globalshortcut.h` | 全局唤出信号、默认快捷键和注册结果通知 | UI 不依赖后台线程；内部类型在 `shortcut_p.h` |
| `windowintegration.h` | 面板几何、卡片尺寸、背板、窗口归属、激活、关闭通知及弹窗装饰 | GUI 线程调用；观察器随所属窗口销毁 |
| `menuintegration.h` | 原生菜单弹出、标准设置/退出动作和菜单布局约定 | GUI 线程调用；动作触发后的业务行为仍由 UI 决定 |
| `applicationintegration.h` | 应用激活策略、首次启动与第二实例的显示约定 | 创建 QApplication 后调用 |
| `fileicon.h` | 文件图标查询与原生图标转换 | GUI 线程调用；返回 `QIcon` |
| `paths.h` | 数据库和翻译目录 | 不访问 SQL；目录准备由存储工作线程负责 |
| `startupintegration.h` | 查询和修改系统开机启动项及权限提示 | 状态来自系统项；公共层校验输入，平台实现返回错误 |

这是一组按职责划分的小接口。无需运行时插件或平台类型判断，CMake 已经知道目标系统，
因此只编译一个系统的实现。Windows 与 Linux 相同的 Qt 行为放在 `desktop/`，原生代码留在各自目录。
UI 使用有明确名称的能力与布局配置，例如 `nativeControls`、`nativeBackdrop`、`hideForDialog`，
不推断当前系统名称。主题颜色和交互动画仍由公共 UI 管理。

## 保持现有行为

- 三个平台共用 `DiagnosticLog` 的 Qt/C++ 实现，负责结构化元数据的时间戳、
  去重、写入和大小轮换。日志位于应用数据目录的 `logs/clipboard.jsonl`，
  单份最多 1 MiB，仅保留当前文件和上一份 `.1`；不加入 WebDAV 同步。
  macOS 适配器用 AppKit 读取原生类型声明，Windows 读取原生格式编号/名称及所有者进程，
  Linux 读取 Qt/X11 格式声明；格式采集不读取文字、图片或文件路径载荷。
  各后端只提交自己的系统元数据，公共日志实现没有系统 SDK 或条件分支。
- macOS 在读取内容前检查原生剪贴板类型，遵循 [NSPasteboard 标记约定](https://nspasteboard.org/)，
  排除 `TransientType`、`AutoGeneratedType`、`ConcealedType` 及其已知旧标记。
  标记只需存在，值为空也生效；多条目的剪贴板任意一项带标记时整次写入都跳过。
  被排除的写入仍通知应用层，以取消上一次等待中的采集；读取后再次核对许可。
  这些内容不会进入历史、数据库或同步。无需读取标记或被排除内容的载荷。
  不按应用名称或临时文件路径推断复制意图，也不依赖 Cmd+C；未标记的普通复制照常记录。
  系统不能保证未标记内容来自用户主动操作，已有历史也不会因此自动删除。
  原生变化及采集许可检查在本机日志留下诊断信息：
  时间、系统变化编号、各条目的格式名称、前台应用和过滤结果。
  前台应用仅表示当时的前台上下文，不能据此断言它是实际写入方。
- macOS 使用 Shift+Cmd+V，运行时没有 Dock 项；面板贴屏幕底部，使用 AppKit 背板和菜单。
  全屏空间切换通知、弹窗激活保护、原生关闭按钮和高分辨率来源图标仍由 macOS 实现处理。
  面板使用状态窗口层级，预览仅高一级，覆盖 Dock 但位于标准菜单和截图遮罩之下。
  面板菜单与条目右键菜单共用原生菜单外观；右键菜单按点击位置弹出，
  等菜单关闭后执行所选动作，原条目已被移除时取消操作。
  原生菜单通过 QMenu 的公开 macOS 转换接口取得标签、快捷键和图标，
  由 AppKit 跟踪选择，再通过公开的 QAction 接口执行动作，不依赖 GuiPrivate。
  跟踪结束后通过 NSResponder 补齐被菜单消费的鼠标释放，
  避免后续左键仍被送到原条目；动作在临时菜单销毁前同步触发，
  不需要递送 Qt 内部菜单项的排队调用。
- Windows 保留 Win+V 及注册失败时的回退、来源图标工作线程、窗口模糊和目标窗口粘贴。
  主面板使用原生 Acrylic 背景，旧版 Windows 10 回退普通模糊；卡片继续使用实色。
  背板成功启用后公共 UI 才降低背景不透明度；系统关闭透明效果、高对比度或接口失败时
  使用实色背景。主题、窗口句柄和尺寸变化更新原生材质及顶部圆角裁切。
- Linux 保留 Ctrl+Shift+V、X11 来源查询、Selection 写入、Shift+Insert 注入以及用户 autostart 文件。
- 数据库位置、schema 和 Qt 信号的队列化 SQL 执行方式没有迁移。
  历史统一保留最近 30 天，由 `core/historypolicy.h` 定义期限与到期边界；
  启动及记录新复制时清理已满 30 天的条目，删除后继续检查移入当前位置的条目。
- 预览持有独立的数据副本，复制引起历史条目重新置顶时仍保持打开。
  “复制到剪贴板”显示短暂的“已复制”提示；“粘贴”关闭面板并贴入原应用。
  关闭预览后按内容标识恢复到重新置顶的条目，两种操作共用 `ClipboardController` 的剪贴板写入方式。
- 图片内存策略位于公共 `ClipboardData`：历史原图保留数据库中的 PNG 字节，
  卡片使用最大 1024 像素的缩略图并显示原图尺寸，预览和复制时按需读取原图。
  新图片由仓库门面取得值快照，数据库线程编码 PNG 后通知历史服务，
  服务按唯一插入请求编号匹配条目并释放展开图；撤销和预览副本共享不可变压缩字节。
  运行时保留 RGB 图像原有格式和 Retina 比例；新复制的灰度、高精度图像，
  或超过 Qt 解码内存上限的图像继续保留展开图，避免改变色彩、精度或无法再次解码。
  其他 MIME 格式及其优先级保持不变。
- 单独的有效本地路径通过公共 `FilePreview` 识别，卡片标注“文件路径”，
  显示文件图标或图片缩略图；路径文本的原始 MIME 数据与粘贴内容保持不变。
  单张图片文件或图片路径的空格预览显示图片，读取时限制预览尺寸，解码失败则回退文件图标。
- 文件同时附带 HTML 或图片格式时，历史重载优先展示本地文件引用，
  与新复制和撤销后的卡片类型一致；文件已失效时仍可使用附带内容。
- macOS 的普通文件和文件夹图标通过 Qt 的 Cocoa 图标服务获取，保留系统文件类型外观。
  图片文件仍展示缩略图。
- macOS 13 及以后通过 `SMAppService.mainAppService` 管理当前应用的系统登录项，
  不需要辅助进程。设置开关读取系统状态，注册失败时恢复实际值并显示错误；
  系统要求用户批准时提示前往「系统设置 → 通用 → 登录项」，不会显示虚假的已启用状态。
  返回设置窗口时重新查询状态，以同步用户在系统设置里的修改。
  旧版 macOS 或直接运行脱离 `.app` 的可执行文件时，开关不可用并说明原因。

## macOS 应用签名

系统登录项要求有效的应用签名。翻译放在 `.app/Contents/Resources`，
最终资源准备完成后签署应用；翻译变动也会触发重新链接和签名。
默认使用本地开发的 ad hoc 签名，可通过 CMake 的
`PASTES_MACOS_SIGNING_IDENTITY` 指定正式签名身份。
这里签署当前构建的应用，不包含发布时的依赖打包和公证流程。

## 扩展一个平台能力

1. 先确定职责，在对应公共头文件声明 Qt/C++ 类型的接口，并说明线程和生命周期约束。
2. 在各系统目录提供实现；真实共用的 Qt 行为放到公共层或 `desktop/`。
3. 在 `platform/CMakeLists.txt` 的对应分支加入源码和系统依赖。
   应用打包资源及翻译生成由根 CMake 管理。
4. UI 只调用公共接口，不包含 Win32、X11、AppKit 或 Carbon 头文件，也不包含 `_p.h`。
5. 更新翻译，编译目标系统，并验证真实交互。纯编译成功不能代表全屏、焦点或粘贴行为正确。

## 重构前的平台验证记录

以下是现有平台实现此前的验证记录，不代表本轮分层重构已在这些系统重新执行。
本轮验证范围和测试命令见 [工程架构](architecture.md#验证与开发)。

macOS 完成构建及原生复制监听、目标粘贴、权限不足回退、原生菜单、弹窗装饰、
设置滚动、激活保护、快捷键与卡片选择检查。全屏唤出和空间切换隐藏检查通过。
重构时发现的全屏预览焦点问题另行修复：实际 PreviewDialog 使用平台预览窗口接口，
在当前全屏空间接收键盘输入；窗口归属判断跨过独立窗口边界，关闭预览后恢复面板焦点。
面板因空间切换隐藏时，预览也会退出，避免留下模态状态。
预览、设置和关于使用一致的 14pt 原生红绿灯；预览的紧凑布局通过平台外观配置提供。
解锁后完成两个真实全屏空间的复验：快捷键唤出、预览层级、关闭后的条目焦点恢复、
切换空间时隐藏和退出模态状态均通过。
文本和图片在同一预览中先复制后粘贴、复制提示复原和关闭后的条目焦点恢复均通过。
原生右键按下和松开、Esc/菜单外点击关闭，以及之后连续左键选择完成复验；
实际鼠标点击原生菜单的复制、纯文本复制、预览和删除均完成复验，
各动作之后左键仍可选择其他条目。

开机启动使用独立应用标识完成系统注册、跨进程状态读取、重复启用和取消检查。
真实鼠标点击设置开关、重新打开设置、激活时同步外部变更，以及无效签名导致注册失败后
恢复关闭状态并显示错误均通过；测试登录项已清除。
应用签名与增量翻译构建另行检查。未实际注销或重启系统，
旧版 macOS 的不可用提示和系统撤销批准的提示分支未在对应环境中实测。

共享 desktop 实现及 Linux 的 Qt 路径、启动服务做了额外语法编译检查。
本机缺少 Linux 的 GDesktopAppInfo、Xt/XTest 等完整头文件，Windows 和 Linux 的完整构建
与原生运行需要各自的环境；现有 CI 的构建入口保持不变。
